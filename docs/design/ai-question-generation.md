# 設計メモ：ファイル添付からの問題自動生成

状態：**未実装**。実装前に、AGENTS.md に従って変更計画を出し、承認を得る。

## 目的

講義資料やノートを添付すると、一問一答カードの候補ができる。
カード作りの手間を減らし、学んだ当日に解き始められるようにする。

## 時期と前提

- 推奨は第7週。認証（第5週）とファイル保存（第6週）が先に必要になる。
- 認証前に公開すると、誰でも無料枠を使い切れる。
- 第4週に前倒しする場合は、端末ごとと全体の1日の利用回数制限を必須にする。

## 全体の流れ

```
添付 → 文字の抽出 → 圧縮 → 生成（Gemini、失敗したらローカル）
     → 検証 → 本人が確認・修正 → カードとして保存
```

- 生成と保存を分ける。**本人が確認していない候補は保存しない。**
- 保存は今ある `POST /api/cards` を使い、新しい経路を作らない。

## 設計方針

### 検証の入口は1つ
AIの出力は信用せず `unknown` として受け、手入力と同じ `parseCardDraft` / `parseQuizCardInput` を通す。通らない候補は捨てる。

### プロンプト圧縮
`src/domain/` の純粋関数にする。

- 余分な空白、ページ番号、繰り返しのヘッダー・フッターを除く。
- 同じ段落の重複を除く。
- 使う範囲（ページや見出し）を本人が選べるようにする。
- 入力の文字数に上限を置き、超えたら切らずに範囲の選び直しを求める。
- 学習の傾向を渡すときは、履歴全文ではなく `SubjectStats`（科目・正答率・誤答原因の件数）だけにする。

### 出力上限
- 問題数（例：1回10問）と出力トークンの両方に上限を置く。
- 出力の形をスキーマで指定する。
- 途中で切れた応答は、完成している問題だけを採用する。

### モデル切替
- モデル名はコードに書かず、環境変数で優先順に並べる。
- 利用上限の到達や一時的な障害なら次のモデルへ移る。入力の誤りなら移らず、利用者に伝える。
- 1回の操作で呼ぶ回数と、全体の待ち時間に上限を置く。

### ローカルフォールバック
APIが使えないときも動き続けるよう、規則だけで候補を作る純粋関数を用意する。

- 「AとはB」「A：B」「A（B）」などの形から、問いと答えを作る。
- AIと同じ型を返し、後の処理を分けない。
- 画面に「簡易生成」と示し、品質の違いを隠さない。

### 差し替えられる境界
```ts
type QuestionGenerator = (source: string, limit: number) => Promise<CardDraft[]>;
```
Geminiとローカルの両方をこの形にし、テストではスタブに替える。

## 安全

| 懸念 | 対策 |
|---|---|
| 鍵の漏洩 | `GEMINI_API_KEY` はサーバー専用。`NEXT_PUBLIC_` を付けない |
| 無料枠の使い切り・悪用 | 認証必須、利用者ごとと全体の1日の回数制限 |
| 資料に紛れた指示文 | 資料は指示ではなくデータとして渡す。出力は検証を通し、本人が確認する |
| 誤った問題 | 保存前の確認を必須にし、元の文を並べて見せる |
| 大きすぎるファイル | 種類・サイズ・ページ数を制限し、サーバーでも検証する |
